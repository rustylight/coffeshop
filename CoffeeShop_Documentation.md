ИНФОРМАТИВНЫЙ РЕФЕРАТ

Проектирование информационной системы для автоматизации управления кофейней.

Курсовая работа состоит из: введения, теоретической части, практической части, заключения, списка использованных источников.

Объём курсовой работы составляет __ страниц, содержит 3 приложения, __ рисунков, __ таблиц, 10 источников, из которых 4 — электронные ресурсы.

Объектом исследования является деятельность по управлению кофейней: учёт меню, обработка заказов, управление бонусной программой лояльности и контроль рабочих смен. Предметом курсовой работы является разработка информационной системы для автоматизации управления кофейней. Актуальность курсовой работы заключается в росте сегмента specialty-кофеен и необходимости централизованного учёта заказов, персонала и бонусной программы.

Цель курсовой работы — анализ предметной области и разработка автоматизированной информационной системы управления кофейней.

Методы проведения работы — теоретические: теоретический анализ и синтез, сравнение, моделирование; эмпирические — изучение литературы, Интернет-источников.

Результатом курсовой работы является готовый программный продукт, разработанный в среде Microsoft Visual Studio на языке C# (.NET 8): десктопный клиент WPF с базой данных PostgreSQL.

Теоретическая значимость работы заключается в расширенном анализе существующего уровня автоматизации предприятий общественного питания и инструментов реализации поставленной задачи.

Практическая значимость курсовой работы заключается в использовании автоматизированной информационной системы для оптимизации управления заказами, меню, персоналом и бонусной программой кофейни.


ВВЕДЕНИЕ

Рынок кофеен в России демонстрирует устойчивый рост: по данным аналитиков, количество кофеен ежегодно увеличивается на 10–15%, при этом значительная часть небольших заведений продолжает вести учёт заказов вручную — в тетрадях и электронных таблицах. Это приводит к ошибкам при расчёте итоговых сумм, утрате данных о клиентах, невозможности оперативного контроля выручки за смену и отсутствию мотивационных программ для персонала.

Цель курсовой работы — анализ предметной области и разработка автоматизированной информационной системы управления кофейней.

Для достижения поставленной цели определены следующие задачи:
- спроектировать программный продукт на основе анализа предметной области и исходных данных;
- разработать UML-диаграммы и ER-диаграмму базы данных;
- реализовать информационную безопасность разрабатываемой системы;
- разработать обучающую документацию для пользователей разрабатываемой системы.

Методы проведения работы:
- теоретические: анализ и синтез, сравнение, моделирование;
- эмпирические: изучение литературы, Интернет-источников, тестирование программного продукта.

Объектом исследования является деятельность по управлению кофейней: учёт меню, обработка заказов, управление бонусной программой лояльности и контроль рабочих смен персонала.

Предметом исследования является информационная система (далее — ИС) автоматизации управления кофейней.

Результат курсовой работы:
- десктопный клиент на платформе WPF (.NET 8), библиотека MaterialDesignInXamlToolkit;
- база данных PostgreSQL: 10 таблиц, 7 триггеров, 3 хранимые процедуры, 3 функции, 3 представления.


1 ТЕОРЕТИЧЕСКАЯ ЧАСТЬ

1.1 Анализ предметной области

Кофейня представляет собой предприятие общественного питания, специализирующееся на приготовлении и продаже кофейных напитков, чая и сопутствующей продукции (десерты, снэки). Управление кофейней включает ведение меню с категориями позиций, обработку заказов клиентов, управление рабочими сменами баристов, ведение бонусной программы лояльности и формирование финансовой отчётности.

Информационная система CoffeeShop предназначена для автоматизации перечисленных процессов. Целевая аудитория — администраторы, баристы и клиенты кофейни.

Система предусматривает три роли пользователей:
- Администратор — полный доступ ко всем разделам: дашборд с KPI, управление персоналом (баристами), управление меню, управление сменами, отчёты по сменам с экспортом в Excel;
- Бариста — просмотр активных заказов, изменение статусов заказов (принять в работу → готов → выдан клиенту), просмотр выполненных заказов, просмотр заработка за смену;
- Клиент — просмотр меню по категориям, формирование корзины, применение бонусов при оплате, оформление заказа, отслеживание статуса заказа, просмотр истории заказов, редактирование профиля.

Функциональные требования к ИС:
- авторизация и регистрация — вход по номеру телефона и паролю с BCrypt-хешированием, регистрация новых клиентов;
- управление меню — добавление, редактирование позиций меню, распределение по категориям (Кофе, Чай, Десерты, Снэки), переключение доступности;
- обработка заказов — создание заказа из корзины, жизненный цикл: pending → in_progress → ready → completed, автоматический пересчёт сумм триггером;
- бонусная программа — начисление 5% бонусов от суммы завершённого заказа, списание бонусов при оформлении нового заказа, история транзакций;
- управление сменами — открытие и закрытие смен администратором, автоматический расчёт выручки, начисление 10% баристам и 3% администратору;
- отчётность — сводные отчёты по сменам, детализация по баристам, экспорт в Excel (ClosedXML).

Нефункциональные требования к ИС:
- операционная система — Windows 10/11 (x64);
- минимальный объём оперативной памяти — 512 МБ;
- разрешение экрана — от 1280×720;
- локализация — русский язык интерфейса;
- валидация данных — на уровне базы данных (CHECK-ограничения) и Entity Framework.


1.2 Постановка задач и выбор технологий

На основе анализа предметной области определены технические задачи: реализация десктопного приложения, проектирование реляционной базы данных с 10 таблицами и объектами БД, реализация системы аутентификации, разработка бонусной программы, разработка модуля отчётности.

В качестве языка программирования выбран C#. По сравнению с Python, C# обладает строгой статической типизацией, что снижает количество ошибок на этапе компиляции и упрощает рефакторинг крупных проектов. В отличие от Java, C# обеспечивает более тесную интеграцию с операционной системой Windows и предоставляет современный синтаксис (LINQ, async/await, pattern matching), повышающий читаемость и продуктивность кода.

В качестве фреймворка пользовательского интерфейса выбран WPF (Windows Presentation Foundation). В отличие от Windows Forms, WPF поддерживает декларативную разметку XAML, привязку данных (Data Binding) и гибкую систему шаблонов элементов управления. WPF предоставляет возможности стилизации интерфейса через MaterialDesignInXamlToolkit, что позволяет реализовать современный дизайн в стилистике кофейни с использованием тёплой цветовой палитры.

В качестве СУБД выбрана PostgreSQL. По сравнению с MySQL, PostgreSQL обеспечивает полноценную поддержку триггеров, хранимых процедур на языке PL/pgSQL, представлений и сложных типов данных (JSONB, массивы). В отличие от Microsoft SQL Server, PostgreSQL является полностью свободным ПО с открытым исходным кодом, что исключает лицензионные затраты. SQLite не рассматривался, поскольку не поддерживает многопользовательский доступ и хранимые процедуры.

Взаимодействие с базой данных осуществляется через Entity Framework Core 8 — ORM-фреймворк, автоматизирующий маппинг объектов C# на таблицы PostgreSQL. EF Core поддерживает Fluent API для конфигурации моделей и параметризованные LINQ-запросы, исключающие SQL-инъекции.

Функция 1: Автообновление поля updated_at

Функция fn_update_timestamp автоматически обновляет поле updated_at при любом изменении записи. Применяется ко всем таблицам через триггеры trg_users_updated_at, trg_menu_items_updated_at, trg_shifts_updated_at, trg_orders_updated_at, trg_staff_earnings_updated_at.

```sql
CREATE OR REPLACE FUNCTION fn_update_timestamp()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$;
```

Функция 2: Пересчёт суммы заказа при изменении позиций

Функция fn_recalculate_order_total автоматически обновляет total_amount и final_amount в таблице orders при любом изменении order_items.

```sql
CREATE OR REPLACE FUNCTION fn_recalculate_order_total()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE
    v_order_id INTEGER;
BEGIN
    IF TG_OP = 'DELETE' THEN
        v_order_id := OLD.order_id;
    ELSE
        v_order_id := NEW.order_id;
    END IF;

    UPDATE orders
    SET
        total_amount = (
            SELECT COALESCE(SUM(subtotal), 0.00)
            FROM order_items WHERE order_id = v_order_id
        ),
        final_amount = (
            SELECT COALESCE(SUM(subtotal), 0.00)
            FROM order_items WHERE order_id = v_order_id
        ) - bonus_used
    WHERE id = v_order_id;

    IF TG_OP = 'DELETE' THEN RETURN OLD;
    ELSE RETURN NEW;
    END IF;
END;
$$;
```

Функция 3: Логирование изменений статуса заказа

Функция fn_log_order_status при каждом изменении status в таблице orders создаёт запись в audit_log со старым и новым значением.

```sql
CREATE OR REPLACE FUNCTION fn_log_order_status()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    IF OLD.status IS DISTINCT FROM NEW.status THEN
        INSERT INTO audit_log (table_name, record_id, action,
                               old_values, new_values, changed_by)
        VALUES (
            'orders', NEW.id, 'STATUS_CHANGE',
            jsonb_build_object('status', OLD.status),
            jsonb_build_object('status', NEW.status,
                               'barista_id', NEW.barista_id),
            NEW.barista_id
        );
    END IF;
    RETURN NEW;
END;
$$;
```

Хранимая процедура 1: Создание заказа (sp_create_order)

Процедура принимает ID клиента, JSON-массив позиций и сумму бонусов к списанию. Выполняет: проверку бонусного баланса, поиск текущей открытой смены, создание заказа и позиций, списание бонусов.

```sql
CREATE OR REPLACE PROCEDURE sp_create_order(
    IN  p_client_id  INTEGER,
    IN  p_items      JSONB,
    IN  p_bonus_used DECIMAL(10,2),
    INOUT p_order_id INTEGER DEFAULT NULL
)
LANGUAGE plpgsql AS $$
DECLARE
    v_item           JSONB;
    v_price          DECIMAL(10,2);
    v_client_bonus   DECIMAL(10,2);
    v_current_shift  INTEGER;
BEGIN
    SELECT bonus_balance INTO v_client_bonus
    FROM users WHERE id = p_client_id AND is_active = TRUE;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Клиент % не найден', p_client_id;
    END IF;

    IF p_bonus_used > v_client_bonus THEN
        RAISE EXCEPTION 'Недостаточно бонусов';
    END IF;

    SELECT id INTO v_current_shift
    FROM shifts WHERE is_closed = FALSE
    ORDER BY opened_at DESC LIMIT 1;

    INSERT INTO orders (client_id, status, bonus_used, shift_id)
    VALUES (p_client_id, 'pending', p_bonus_used, v_current_shift)
    RETURNING id INTO p_order_id;

    FOR v_item IN SELECT * FROM jsonb_array_elements(p_items)
    LOOP
        SELECT price INTO v_price FROM menu_items
        WHERE id = (v_item->>'menu_item_id')::INTEGER
          AND is_available = TRUE;

        INSERT INTO order_items (order_id, menu_item_id,
                                 quantity, unit_price, subtotal)
        VALUES (p_order_id, (v_item->>'menu_item_id')::INTEGER,
                (v_item->>'quantity')::INTEGER, v_price,
                v_price * (v_item->>'quantity')::INTEGER);
    END LOOP;

    UPDATE orders SET final_amount = total_amount - p_bonus_used
    WHERE id = p_order_id;

    IF p_bonus_used > 0 THEN
        UPDATE users SET bonus_balance = bonus_balance - p_bonus_used
        WHERE id = p_client_id;
    END IF;
END;
$$;
```

Хранимая процедура 2: Завершение заказа (sp_complete_order)

Процедура переводит заказ в статус completed, начисляет 5% бонусов клиенту, 10% бариста в staff_earnings, обновляет выручку смены.

```sql
CREATE OR REPLACE PROCEDURE sp_complete_order(
    IN p_order_id  INTEGER,
    IN p_barista_id INTEGER
)
LANGUAGE plpgsql AS $$
DECLARE
    v_order         RECORD;
    v_bonus_accrual DECIMAL(10,2);
    v_barista_earn  DECIMAL(10,2);
    v_shift_id      INTEGER;
BEGIN
    SELECT * INTO v_order FROM orders WHERE id = p_order_id;

    v_shift_id := v_order.shift_id;

    IF v_shift_id IS NULL THEN
        SELECT id INTO v_shift_id FROM shifts
        WHERE is_closed = FALSE
        ORDER BY opened_at DESC LIMIT 1;
    END IF;

    v_bonus_accrual := ROUND(v_order.final_amount * 0.05, 2);

    UPDATE users
    SET bonus_balance = bonus_balance + v_bonus_accrual
    WHERE id = v_order.client_id;

    IF v_shift_id IS NOT NULL THEN
        v_barista_earn := ROUND(v_order.final_amount * 0.10, 2);

        INSERT INTO staff_earnings (user_id, shift_id, orders_count,
            orders_total, earning_percent, earned_amount)
        VALUES (p_barista_id, v_shift_id, 1,
            v_order.final_amount, 10.00, v_barista_earn)
        ON CONFLICT (user_id, shift_id) DO UPDATE
            SET orders_count = staff_earnings.orders_count + 1,
                orders_total = staff_earnings.orders_total
                             + v_order.final_amount,
                earned_amount = staff_earnings.earned_amount
                              + v_barista_earn;

        UPDATE shifts
        SET total_revenue = total_revenue + v_order.final_amount
        WHERE id = v_shift_id;
    END IF;

    UPDATE orders
    SET status = 'completed', barista_id = p_barista_id
    WHERE id = p_order_id;
END;
$$;
```

Хранимая процедура 3: Закрытие смены (sp_close_shift)

Процедура начисляет 3% от выручки администратору, закрывает смену и записывает событие в audit_log.

```sql
CREATE OR REPLACE PROCEDURE sp_close_shift(
    IN p_shift_id INTEGER,
    IN p_admin_id INTEGER
)
LANGUAGE plpgsql AS $$
DECLARE
    v_shift       RECORD;
    v_admin_earn  DECIMAL(10,2);
BEGIN
    SELECT * INTO v_shift FROM shifts WHERE id = p_shift_id;

    v_admin_earn := ROUND(v_shift.total_revenue * 0.03, 2);

    INSERT INTO staff_earnings (user_id, shift_id, orders_count,
        orders_total, earning_percent, earned_amount)
    VALUES (p_admin_id, p_shift_id, 0,
        v_shift.total_revenue, 3.00, v_admin_earn)
    ON CONFLICT (user_id, shift_id) DO UPDATE
        SET earned_amount = EXCLUDED.earned_amount;

    UPDATE shifts
    SET is_closed = TRUE, closed_at = NOW()
    WHERE id = p_shift_id;

    INSERT INTO audit_log (table_name, record_id, action,
                           new_values, changed_by)
    VALUES ('shifts', p_shift_id, 'CLOSE_SHIFT',
        jsonb_build_object('total_revenue', v_shift.total_revenue,
                           'admin_earn', v_admin_earn),
        p_admin_id);
END;
$$;
```

CREATE OR REPLACE VIEW v_shift_report AS
SELECT s.id, s.opened_at, s.closed_at, s.is_closed,
       s.total_revenue,
       u.full_name AS admin_name,
       COUNT(o.id)  AS orders_count

    AND o.status = 'completed'

2.4 Обеспечение информационной безопасности

Хеширование паролей

Для хранения паролей используется алгоритм BCrypt (библиотека BCrypt.Net-Next) с автоматической генерацией salt и настраиваемым cost factor. Хеши хранятся в таблице users в поле password_hash и не подлежат обратному преобразованию.

```csharp
// Хеширование пароля при создании пользователя
string hash = BCrypt.Net.BCrypt.HashPassword(password);

// Верификация пароля при входе
bool isValid = BCrypt.Net.BCrypt.Verify(inputPassword, storedHash);
```

Разграничение доступа

Система реализует ролевую модель доступа на уровне приложения. После авторизации SessionManager сохраняет текущего пользователя и его роль. В зависимости от роли загружается соответствующий Shell-интерфейс:
- Администратор → AdminShell (дашборд, персонал, меню, отчёты);
- Бариста → BaristaShell (активные заказы, выполненные, заработок);
- Клиент → ClientShell (меню, заказ, история, профиль).

Защита от SQL-инъекций

Все запросы к базе данных выполняются через Entity Framework Core, который автоматически параметризует LINQ-запросы. Хранимые процедуры вызываются через параметризованные вызовы, исключая возможность внедрения SQL-кода.

Журнал аудита

Таблица audit_log фиксирует все изменения статусов заказов через триггер fn_log_order_status, а также события закрытия смен. Записи содержат старые и новые значения в формате JSONB, идентификатор пользователя и временную метку.
